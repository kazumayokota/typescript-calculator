# 共通処理実装記録

## 1. 実施範囲

実装手順書の「フェーズ4：共通計算処理の実装」を実施した。処理は`app/src/logic`へ配置し、ReactとDOMには依存していない。その後のフェーズ5でUIからreducerを利用しているが、共通処理側の依存関係は変更していない。

## 3. 実装内容

### 数字と小数点

- 空表示への数字入力はその数字を設定する。
- 表示が`0`の場合、次の数字で置換する。
- それ以外は末尾へ数字を追加する。
- 空表示への小数点入力は無視する。
- すでに小数点がある場合は追加しない。

### 演算子

- 内部値`add`、`subtract`、`multiply`、`divide`を使用する。
- 表示時だけ`+`、`-`、`×`、`÷`へ変換する。
- S0での演算子入力は無視する。
- S1では計算2を計算1へ移動する。
- S2では末尾演算子を置換する。
- S3では即時計算後に新しい演算子を設定する。

### 計算

- `decimal.js`で10進数演算する。
- JavaScriptの`number`では小数演算しない。
- 小数点以下15桁へ`Decimal.ROUND_HALF_UP`で四捨五入する。
- 不要な末尾`0`を表示しない。
- 負のゼロを`0`へ正規化する。
- 0除算は詳細設計書どおり`0`とする。
- 演算子優先順位を使わず、左から順に計算する。

整数部の最大桁数は仕様で未定義である。Decimalの計算精度は、左右の入力桁数と結果の小数15桁を基に計算ごとに確保し、固定の低い有効桁数による切り捨てを避けている。

## 4. reducer

stateは次の2項目だけである。

```ts
type CalculatorState = Readonly<{
  strDisplay1: string;
  strDisplay2: string;
}>;
```

設計書にない結果表示フラグ、待機フラグ、エラー状態、直前演算は追加していない。actionは`strType`で網羅的に分岐し、stateを直接変更しない。

## 5. 主な検証ケース

| ケース | 期待結果 |
| --- | --- |
| `0.1 + 0.2` | `0.3` |
| `1 ÷ 3` | `0.333333333333333` |
| `2 ÷ 3` | `0.666666666666667` |
| 小数16桁目が4 | 切り捨て側 |
| 小数16桁目が5 | 四捨五入で繰り上げ |
| 負数の小数16桁目が5 | 絶対値を繰り上げ |
| `8 ÷ 0` | `0` |
| `2 + 3 × 4 =` | `20` |
| 演算子の連続入力 | 末尾演算子を置換 |
| `=`の連続入力 | 2回目は状態維持 |
| 結果`3`の後に`4` | `34` |
| `C` | 両表示を空にする |
| `CE` | 計算2だけを空にする |
